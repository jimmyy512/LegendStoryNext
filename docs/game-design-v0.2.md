# 《口袋江湖》v2｜初步設計草案 v0.2

本版以舊作《口袋江湖》的門派人物、第一章故事與角色養成為基礎，改為 **2D 俯視探索＋獨立回合制戰鬥**，使用 **Pixi.js** 製作電腦瀏覽器遊戲。

保留「初入江湖、拜師學藝、發現門派秘密」的主題。場景全部重畫，地圖配置、操作與戰鬥規則依新玩法重新設計。

## 一、遊戲定位

玩家扮演初入江湖的年輕俠客，拜入全真派，在與師兄弟相處、接受委託和探索禁地的過程中，建立自己的武學路線，並逐步發現門派中未解的往事。

核心體驗是「探索、選擇、武學成長」。第一階段製作能從頭玩到結尾的單機短篇，再沿用既有系統擴充洛陽與後續江湖故事。

| 項目 | v2 方向 |
|---|---|
| 專案名稱 | 口袋江湖 |
| 工作目錄 | `LegendStoryNext` |
| 舊版用途 | `LegendStory` 作為劇情、人物與系統參考 |
| 主要平台 | 電腦瀏覽器優先，介面預留手機適配 |
| 開發技術 | Pixi.js＋TypeScript |
| 探索形式 | 暫採 2D 俯視地圖，點擊移動與互動 |
| 戰鬥形式 | 獨立戰鬥畫面、傳統回合制 |
| 遊玩方式 | 單人、可存檔與讀檔 |
| 主角設定 | 固定身世與主線角色，可自訂姓名、選擇武學路線 |
| 美術 | 場景全部重畫，正式風格待定 |

## 二、與舊作的關係

舊作已經具備第一章故事、六位門派 NPC、裝備換裝、交易、任務與存檔，是 v2 的內容基礎。

| 舊作內容 | v2 處理方式 |
|---|---|
| 拜師、剿賊、後山禁地與師兄往事 | 保留故事骨架，調整節奏與鋪陳 |
| 全真派人物關係 | 保留人物定位，整理動機與對話 |
| 森林、全真派、後山、洞穴 | 重畫為適合俯視探索的新地圖 |
| 橫向移動、二段跳、屋頂平台 | 改為道路、高低區域、捷徑與探索事件 |
| 即時普攻與技能 | 重新設計成回合制招式 |
| 裝備、背包、商店與補藥 | 保留功能，簡化第一版數值與品項 |
| 洛陽 | 保留為第一章結尾與後續章節方向 |
| 士兵指揮戰鬥模式 | 暫不納入第一階段 |
| 舊雲端存檔 | 第一版改用瀏覽器本機存檔 |

舊作的攻擊動畫與技能名稱可以作為表現參考，傷害、耗魔、狀態與敵人行為需按回合制重新平衡。

## 三、核心遊玩流程

**探索地區 → 與人物互動 → 取得任務與線索 → 選擇處理方式 → 戰鬥或完成事件 → 獲得武學與物品 → 開啟後續劇情。**

例如，玩家受命處理山賊事件，可以直接交戰，也可以先找到受傷的山賊，了解他們出現在山下的原因。兩條路線都能推進主線，但獲得的線索、報酬與人物回應不同。

初期採用「局部分支、回到共同主線」。選擇要有可見結果，但不為每個選項製作完全不同的後續章節。

## 四、第一章故事方向

暫定章名為 **「初入全真」**。

| 段落 | 故事內容 | 玩家體驗 |
|---|---|---|
| 山下相遇 | 主角在前往全真派的途中遇到衝突 | 學習移動、互動與第一場戰鬥 |
| 拜入門派 | 通過簡單考驗，認識掌門與部分師兄弟 | 選擇武學路線、取得初始裝備 |
| 山賊疑雲 | 接受委託處理山下事件 | 探索、支線與第一次重要選擇 |
| 後山禁地 | 調查洞穴異狀與過往事件 | 蒐集線索、準備補給、挑戰敵人 |
| 師兄往事 | 發現二師兄與師妹的秘密 | 首領戰與事件收尾 |
| 啟程洛陽 | 門派事件告一段落 | 呈現選擇結果，留下下一章方向 |

開場不要求玩家先與全部六位 NPC 逐一談話。人物介紹穿插在練功、交易與任務中，讓玩家早些體驗戰鬥與成長。

舊作「為了復活師妹而踏入禁地」的動機值得保留。結局建議重新鋪陳，讓事件留下合理後果。首領身分與最終真相暫不定案。

## 五、回合制戰鬥

### 基本形式

第一版採主角單人對戰，敵方每場約 1～3 名，不包含戰棋格子、移動走位、隊友與連攜。

每一輪開始時，依身法決定敵我行動順序，每個存活角色原則上行動一次。玩家在自己的回合選擇指令，畫面顯示目前順序、生命、內力與狀態。

| 指令 | 用途 |
|---|---|
| 普通攻擊 | 不消耗內力，提供穩定輸出 |
| 武學 | 消耗內力，造成傷害或施加效果 |
| 道具 | 使用藥品等戰鬥物品，消耗本次行動 |
| 防禦 | 降低接下來受到的傷害，持續至下次自身行動 |
| 逃跑 | 一般遭遇戰可嘗試，劇情戰與首領戰另訂限制 |

探索時以可見敵人或事件觸發戰鬥為主，第一版不採隨機踩雷遇敵。戰鬥結束後回到探索地圖，依結果更新任務、敵人與獎勵。

### 武學路線

初期沿用舊作劍法與拳掌的方向，做出兩種不同的決策方式。

| 路線 | 玩法定位 | 招式方向 |
|---|---|---|
| 劍法 | 先削弱對手，再集中攻擊 | 破防、單體重擊 |
| 拳掌 | 承受攻擊，掌握反擊時機 | 護體反擊、強力掌擊 |

第一版共製作四招武學、兩種內功，每條路線各兩招與一種內功。所有角色都有普通攻擊與防禦。

招式負責提供戰鬥行動，內功提供被動效果。初期同時裝備一種內功，避免過早出現大量組合。

### 戰鬥驗證重點

回合制的樂趣應來自觀察與取捨：

- 敵人準備重擊時，防禦是否值得使用。
- 內力有限時，要先破防、直接重擊，還是保留給下一場。
- 多名敵人在場時，先處理哪一名會改變戰局。
- 劍法與拳掌是否產生不同的有效打法。

首領至少有一種能提前辨識的危險行動，讓玩家有機會理解並應對。

## 六、探索、任務與成長

### 地圖與互動

世界由小型地圖組成，透過入口切換。第一章使用森林、全真派、後山與洞穴四張地圖。

點擊地面移動，點擊 NPC 或物件時，角色走到可互動距離後執行動作。地圖包含 NPC、寶箱、可見敵人、入口與事件區域。

舊作屋頂與山崖探索的特色，可以轉成屋頂捷徑、山路岔道與可解鎖通路。是否加入輕功能力，待基本探索完成後評估。

### 任務與對話

支援主線、支線、條件式對話與少量分歧。任務條件包括交付物品、擊敗指定敵人、拜訪人物與取得線索。

對話選項分成一般詢問與關鍵決定。關鍵決定影響獎勵、人物態度或後續對話，並存入進度。

第一版先用具名事件紀錄處理人物反應，例如「曾協助受傷山賊」，暫不建立龐大的門派聲望與善惡數值系統。

### 角色與物品

基本能力使用生命、內力、攻擊、防禦與身法。

成長來源包含升級、任務獎勵、拜師、秘笈與裝備。第一版先做武器、防具、藥品與任務物品，裝備使用固定屬性。

舊作已有外觀換裝，但 v2 首版先完成裝備效果與介面。角色外觀是否同步換裝，需配合新的角色美術與動畫規格決定。

## 七、美術與畫面

**四張探索地圖全部重畫，戰鬥背景與介面配合新視角重新設計。**

| 區域 | 視覺重點 |
|---|---|
| 森林 | 林間道路、山賊活動痕跡與隱藏岔路 |
| 全真派 | 山門、練功院、主殿與人物生活空間 |
| 後山 | 崖壁、石階、雲霧與禁地入口 |
| 洞穴 | 昏暗通道、遺留物件與事件核心區域 |

探索地圖先配置道路、阻擋、互動位置與事件範圍，再繪製正式場景。

俯視探索角色、戰鬥角色與對話立繪需要統一造型，但可以採不同尺寸與表現方式。舊版側面骨骼動畫先作動作參考，是否沿用需另外驗證。

主要畫面包含主選單、探索、對話、戰鬥、角色與武學、背包、商店、任務紀錄、存讀檔及設定。

正式美術暫留兩個方向：

- **像素風**：以一致的像素尺寸、角色比例與動畫規格製作。
- **手繪國風**：以統一筆觸、色彩與人物立繪建立江湖氣氛。

原型使用佔位素材，先驗證地圖與操作尺度，再定正式風格。

## 八、存檔與資料管理

提供手動存檔、關鍵節點自動存檔，以及匯出／匯入備份。

存檔必須包含角色能力、裝備、武學、背包、所在地圖與位置、任務進度、關鍵選擇，以及已領獎勵和已開寶箱。

第一版先支援探索中的安全節點存檔。戰鬥途中與對話選項尚未結束時，不開放手動存檔。自動存檔需等戰鬥結果、獎勵與任務更新全部完成。

每份存檔帶有格式版本，匯入時先檢查資料，避免錯誤檔案覆蓋有效進度。

## 九、開發與 AI 協作方式

Pixi.js 負責畫面與互動，戰鬥、任務、背包、地圖與存檔各自管理規則。

地圖配置、武學、敵人、物品、對話與任務使用固定識別碼和統一資料格式。地圖採可視化工具配置，再匯出資料交由遊戲讀取，具體工具在原型階段選定。

每次完成一個可驗收的小功能，確認後再擴充。內容檢查包含：

- 人物、物品、敵人與對話的引用是否存在。
- 任務是否可完成，分支是否能回到共同主線。
- 獎勵是否只發一次，戰敗重試是否重複取得物品。
- 存讀檔後，寶箱、任務與選擇結果是否一致。
- 任一路線是否可能因缺少任務物品而卡死。

執行時使用預先編寫的劇情與對話，即時 AI NPC 對話暫不納入。

## 十、第一個可玩版本

目標為約 **15～30 分鐘**的第一章短篇。實際長度以試玩調整，不靠重複刷怪延長。

| 內容 | 初步範圍 |
|---|---|
| 探索地圖 | 森林、全真派、後山、洞穴，共四張 |
| 互動人物 | 以舊作六位門派 NPC 為基礎，部分僅提供簡短互動 |
| 劇情 | 一條主線、兩條短支線、一次重要選擇 |
| 敵人 | 三種普通敵人、一位首領 |
| 武學 | 四招武學、兩種內功 |
| 物品 | 約 12～15 種 |
| 完整功能 | 探索、對話、戰鬥、任務、交易、裝備、存讀檔 |

驗收以「能從開局玩到結尾」為核心。兩種武學路線都能通關，關鍵選擇有不同回應，沒有任務卡死、重複領獎或讀檔遺失進度。

## 十一、製作順序

1. **基本原型**
   一張小地圖、一名 NPC、一場回合制戰鬥。確認點擊移動、互動、行動順序與指令操作。

2. **完整任務流程**
   串起接任務、進入戰鬥、取得獎勵、裝備與存讀檔，驗證整體資料流程。

3. **第一章內容與正式美術**
   定下美術規格，逐張重畫場景，補齊四張地圖、主支線與首領戰。

4. **試玩與打磨**
   調整節奏、難度、操作提示、音效與載入，檢查不同視窗尺寸。

第一階段不納入多人連線、玩家交易、戰棋走位、士兵指揮、無縫大世界與大量程序生成。

目前可以確定的是 **Pixi.js、單機、回合制，以及場景重畫**。俯視探索、固定身世但可命名的主角、電腦優先作為這版草案的預設，正式美術風格與第一章結局留待定案。
