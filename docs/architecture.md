# 口袋江湖：程式架構與擴充邊界

目前是第一章的可玩原型，不是完整大型 RPG 框架。先把狀態所有權、場景生命週期、資源與存檔的邊界確立，再用實際章節需求擴充。

## 設計原則

- 有持續狀態與生命週期的部分使用類別，例如旅程、戰鬥、場景、存檔服務。
- 傷害、物品、尋路、存檔驗證等規則保持可獨立測試，不為了物件導向額外包一層空類別。
- 優先組合而不是深層繼承。目前只有探索／戰鬥場景共用薄的 PixiScene。
- 不使用全域遊戲單例。GameApplication 建立服務，外部 I/O 透過介面注入。
- 場景不能直接修改旅程，UI 不能決定獎勵。領獎和任務推進由規則層處理。

## 模組與責任

| 模組 | 負責 | 不負責 |
|---|---|---|
| main | 小型啟動頁、動態載入遊戲、建立依賴 | 劇情與戰鬥 |
| GameApplication | 接收操作，協調對話、切換場景、存讀檔 | 傷害公式、物品價格、地圖繪製 |
| GameSession | 管理一次旅程、狀態寫入、戰鬥開始與結算 | DOM、Pixi、localStorage |
| Battle | 蓄勢、自動普攻、預約招式、部位傷害、勝敗 | 播動畫與寫入存檔 |
| GameView / PanelView | 顯示資料、產生操作入口 | 修改旅程與發獎 |
| World | Pixi Application、更新迴圈、場景掛載 | 任務、背包、戰鬥計算 |
| ExplorationScene | 地圖呈現、尋路與移動表現 | 直接修改任務和玩家能力 |
| BattleScene | 敵我角色、血條、目標與傷害表現 | 決定傷害與掉落 |
| SceneManager / PixiScene | 場景更換、update、dispose | 讀取遠端資源 |
| TransitionController | 換圖鎖定、載入重試、取消與提交順序 | 實際貼圖格式 |
| AssetService | 共用與地圖 bundle、載入進度、舊貼圖釋放 | 修改遊戲進度 |
| SaveRepository | 手動／自動存檔、有效存檔回退 | 格式驗證、UI 提示 |
| game/save | 版本與資料驗證、序列化 | localStorage |

GameSession 對外提供旅程副本，View 和場景持有的資料不會和存檔中的旅程共用參考。Battle 是單場戰鬥的狀態物件，應用層只呼叫其指令並讀取結果，不直接改其欄位。

## 換圖流程

1. Session 檢查入口與任務條件，產生下一張地圖的候選狀態，不修改現有旅程。
2. TransitionController 鎖定操作並暫停移動。
3. AssetService 載入共用資源與新地圖。引擎下載使用不定進度，資源 bundle 顯示實際資源完成比例，不假裝是下載位元組百分比。
4. 載入失敗可以重試，已有旅程時可以返回原畫面。此時舊地圖、舊進度仍在。
5. 建立並掛載新場景後，才提交旅程與自動存檔。
6. 銷毀舊場景的顯示物件和事件，再釋放舊地圖貼圖。共用貼圖常駐。
7. 清理完成後解除操作鎖。

目前戰鬥使用程序繪製角色與背景，沒有獨立戰鬥資源包。未來加入正式角色圖集、特效與音效時，依同樣流程增加 battle bundle。當前場景 SVG 為輪廓紋理與移動標記，正式美術仍待重製。

## Pixi UI 選型

- 採用 [@pixi/ui](https://github.com/pixijs/ui)，MIT 授權，使用 v2 對應 Pixi v8。
- 目前實際使用 ProgressBar 與 ButtonContainer 製作戰鬥血條及 Canvas 目標按鈕。
- 任務、背包、對話、表單維持 DOM/CSS，可直接使用鍵盤、文字排版與無障礙語意。
- 已評估 [Pixi Layout](https://layout.pixijs.io/)，目前不引入 Yoga 排版。等到有大量 Canvas 內面板時，再以具體需求評估。
- 載入採用 [Pixi Assets](https://pixijs.com/8.x/guides/components/assets) bundle，不再自製貼圖快取。

## 內容擴充

### 新增物品、敵人、武學

第一階段先擴充 data/content.ts 的固定識別碼與資料，規則仍使用統一型別。不建立 Sword01、Sword02 等只差數值的繼承類別。

增加新的武學效果時，需先決定它在回合中的生效與失效時間，再增加規則測試。效果種類明顯增多後才抽出 EffectHandler，避免現在就建立大量尚未使用的抽象層。

### 新增地圖

擴充 MapId、data/maps.ts、資源 manifest，以及存檔位置驗證。地圖資料包含碰撞、入口和互動物件。測試會檢查出生點與互動位置是否能到達。

目前只有四張地圖，因此仍是程式內資料。正式美術階段再接地圖編輯器輸出與資料 schema，不把目前 Graphics 示意畫法當作正式場景製作流程。

### 新增章節與任務

story.ts 目前是全真篇專用規則，不是通用任務編輯器。第二章開始前應把條件、對話節點與獎勵拆成章節資料和 action handler，新增章節不應繼續往單一 switch 堆內容。

任務狀態、完成旗標、已擊敗遭遇與已開啟寶箱分開記錄。獎勵必須檢查領取狀態，不依賴按鈕只被點一次。

### 存檔演進

目前 schema version = 2，加入部位耐久。v1 先通過舊結構驗證再補完好部位升級。localStorage key 保留原名稱以讀取既有資料。新增不相容資料時，新增 migration 並保留舊版 fixture 測試，不直接放寬驗證。

未來雲端存檔可以替換 SaveRepository 的介面實作，但網路衝突解決、登入與跨裝置同步尚未實作。

## 驗證與限制

- 自動測試涵蓋劍／掌 × 善意／武力分支的章節規則、重複獎勵、回合效果、存檔驗證、場景清理、載入取消與重試。
- 單元測試的完整章節走法在主要戰鬥前有調息，不代表已完成 15–30 分鐘遊玩時長與平衡驗收。
- 程式中尚有第一章專用判斷。GameApplication 後續若增加更多選單流程，應再拆出獨立 controller，不能變成所有規則的集中處。
- 正式立繪、場景圖集、動畫、音效、手機互動優化與地圖編輯流程尚未完成。
- 引擎 chunk 目前有超過 500 KB 的打包警告。啟動畫面已與引擎分開，不等於已完成低速網路效能驗收。
